## 1. 项目背景与目标

### 1.1 业务背景

工业生产中，旋转机械、气动设备等关键资产长期处于高负荷运转状态。其振动、声压、电流等物理量蕴含着丰富的健康状态信息。NI（National Instruments）的 TDMS 格式是工业数据采集的事实标准。

传统人工巡检 + 阈值告警存在以下痛点：

- TDMS 文件体积大（百 MB 至 GB），难以快速浏览
- 单一 3-Sigma 阈值无法适应非平稳工况
- 缺少系统化的算法对比与评估手段
- 缺少统一的告警闭环管理

### 1.2 设计目标

| 类别 | 目标 |
|------|------|
| 功能性 | 完整覆盖「数据 → 存储 → 检测 → 可视化 → 告警」全链路 |
| 可扩展 | 算法层抽象统一接口，新增算法不影响其他模块 |
| 易用性 | 零配置启动，单机运行，无需 Docker / Redis |
| 可演示 | 自带模拟数据 + 真实 TDMS 兼容，老师无需准备数据 |
| 工程性 | 测试覆盖率 ≥ 80%，分层清晰，文档齐全 |

### 1.3 业务指标

- **准确性**：在合成 ground truth 数据上 F1 > 0.7
- **实时性**：流式检测延迟 < 1 秒
- **健康评估**：0-100 健康分 + 5 级状态（优秀/良好/注意/警告/严重）

### 2.1 总体架构

采用**经典分层架构**，自下而上 5 层：

```

└──────────────────┬──────────────────────────────────┘
                   │ Python 函数调用
┌──────────────────▼──────────────────────────────────┐
│  ④ 业务服务层                                        │
│   ┌─────────┐ ┌─────────┐ ┌─────────┐               │
│   │算法层   │ │流式引擎 │ │健康评分 │               │
│   │ML+统计  │ │后台线程 │ │ 0-100  │               │
│   └─────────┘ └─────────┘ └─────────┘               │
└──────────────────┬──────────────────────────────────┘
                   │ SQLAlchemy ORM
┌──────────────────▼──────────────────────────────────┐
│  ③ 存储层 (SQLite + ORM)                             │
│   devices · channels · signals · alerts · runs      │
└──────────────────▲──────────────────────────────────┘
                   │
```

### 2.3 数据流

#### 2.3.1 离线分析流

```
TDMS 文件
    │ nptdms.read_metadata
    ▼
元数据预览（通道数 / 采样率 / 单位）
    │ 用户配置降采样
    ▼
nptdms.TdmsFile.read + 切片 + 步长采样
    │
    ▼
ChannelData[] (device, channel, ts, values, unit, sr)
    │ insert_signals_bulk (分块 INSERT, WAL)
    ▼
SQLite signals 表
    │ query_signals
    ▼
DataFrame
    │ Detector.fit + predict
    ▼
0/1 标签 + 异常分
    │ update_anomaly_flags + create_alert
    ▼
SQLite (signals.is_anomaly + alerts)
    │
    ▼
Plotly 可视化
```

#### 2.3.2 实时监控流

```
SQLite signals
    │ load 全量
    ▼
StreamEngine 后台线程
    │ time.sleep(1/sr) 推送
    ▼
deque 环形缓冲区（最多 2000 点）
    │ 主线程定期 snapshot()
    ▼
Detector.predict (在缓冲区上)
    │
    ▼
Plotly 实时刷新（uirevision 保持视图状态）
    │
    ▼
健康分动态更新
```

#### 2.4.3 性能优化

```python
PRAGMA journal_mode=WAL          # Write-Ahead Logging，并发友好
PRAGMA synchronous=NORMAL        # 减少 fsync
PRAGMA cache_size=-64000         # 64MB 缓存
PRAGMA temp_store=MEMORY         # 临时表入内存
```

批量插入采用**分块 executemany**（默认 20000 条/块），避免单次事务过大。

## 3. 算法设计

### 3.1 算法对比矩阵

| 算法 | 类型 | 复杂度 | 鲁棒性 | 高维 | 适用场景 |
|------|------|--------|--------|------|---------|
| 3-Sigma | 参数统计 | O(n) | 低 | ✗ | 平稳正态信号 |
| IQR | 非参数 | O(n log n) | 中 | ✗ | 偏态分布 |
| MAD | 鲁棒统计 | O(n log n) | 高 | ✗ | 噪声大、有极值 |
| Isolation Forest | 集成学习 | O(n log n) | 中高 | ✓ | 高维 / 大数据 |
| LOF | 密度法 | O(n²) | 中 | ✓ | 局部异常 |

### 3.2 检测器抽象接口

```python
class BaseDetector(ABC):
    name: str

    def fit(self, x: np.ndarray) -> "BaseDetector":
        """无监督训练；统计法计算阈值，ML 训练模型"""

    @abstractmethod
    def predict(self, x: np.ndarray) -> np.ndarray:
        """返回 0/1 数组，1 表示异常"""

    @abstractmethod
    def score(self, x: np.ndarray) -> np.ndarray:
        """返回每点异常分数，越大越异常"""

    def get_params(self) -> dict:
        """返回当前参数（用于持久化）"""
```

**设计模式**：策略模式（Strategy）+ 工厂模式（Factory）。新增算法只需继承 `BaseDetector` 并注册到 `algorithms/registry.py`。

### 3.3 滑窗特征工程

工业振动信号的异常常常是**统计特征突变**而非单点偏离。系统支持将原始时序转为 6 维特征：

```
窗口 (size=W, step=1)
    ▼
[mean, std, rms, peak-to-peak, kurtosis, skew]
    ▼
ML 模型在特征空间检测
    ▼
窗口标签 → 扩展回原长度（取窗口最后位置）
```

### 3.4 健康评分公式

```python
score = 100 - anomaly_rate_% × 2.0 × max(1, mean_severity / 3.0)
score = clip(score, 0, 100)
```

| 区间 | 等级 | 颜色 |
|------|------|------|
| ≥ 90 | 优秀 | 绿 |
| 75-90 | 良好 | 黄绿 |
| 60-75 | 注意 | 黄 |
| 40-60 | 警告 | 橙 |
| < 40 | 严重 | 红 |

## 4. 关键技术决策

| 决策 | 选择 | 理由 | 备选方案 |
|------|------|------|---------|
| 数据库 | SQLite | 零配置、内置、CRUD 完整 | TimescaleDB（生产级） |
| ORM | SQLAlchemy 2.0 | 类型安全 + 跨数据库 | 裸 sqlite3 |
| UI 框架 | Streamlit | 单文件页面，自动刷新 | Dash / FastAPI+React |
| 流式 | threading + deque | 标准库，无外部依赖 | Redis Streams / Kafka |
| 算法库 | scikit-learn | 工业级、API 统一 | PyOD（更专业但更重） |
| TDMS | nptdms | 业界标准 | 自实现解析器 |
| 测试 | pytest | 生态成熟 | unittest |

## 5. 非功能性设计

### 5.1 性能

- TDMS 元数据解析：< 100 ms（不读数据）
- 20 万点入库：< 2 秒（WAL + 分块）
- IsolationForest 推理 5 万点：< 500 ms
- 实时刷新：300 ms / 帧

### 5.2 可扩展性

- 新增算法：实现 `BaseDetector` + 注册
- 新增数据源：实现 `ingestion/` 下的解析器
- 新增 UI 页：在 `pages/` 下新建文件

### 5.3 可测试性

- 25 个 pytest 测试用例
- 覆盖率 85%
- 算法在合成数据上验证 ground truth

### 5.4 容错

- TDMS 解析失败 → FileNotFoundError 显式抛出
- 算法 fit/predict 异常 → Streamlit 红框提示
- 数据库写入异常 → 自动回滚（SQLAlchemy 事务）

## 7. 风险与限制

| 风险 | 等级 | 缓解措施 |
|------|------|---------|
| SQLite 单点逐行入库慢 | 中 | 降采样 + 分块批量 + WAL |
| LOF O(n²) 不支持百万级 | 中 | UI 限制点数，建议先降采样 |
| 流式仿真非真实采集 | 低 | 仅作教学演示，可对接真实 NI DAQ |
| 检测器无在线学习 | 低 | MVP 范围，未来可加 concept drift |
